Implemented

Each venue now combines service booking and product commerce inside one profile. Tabs separate Services, Shop, and Reviews, while cart and stock awareness drive the commerce flow.

Product Management

  • Owner adds name, price, image, and stock quantity.
  • Out-of-stock products auto-disable purchase action.
  • Stock counts appear at point of purchase.

Cart + Checkout

  • Quantity controls with max stock enforcement.
  • Checkout writes `orders` collection records.
  • Stock decremented after order placement.

Technical Readout

Implementation

Architecture remains intentionally lean for velocity: single-page frontend with Firebase-backed auth and persistence, supporting role-aware rendering and transactional updates.

Application Stack

  • Frontend: HTML5, CSS3, Vanilla JavaScript
  • Data: Firestore collections for users, stores, bookings, orders, offers
  • Auth: Firebase Authentication with role-based UI switching
  • Storage: Firebase Storage for media assets

Transaction Integrity

  • Checkout writes order records and decrements product stock.
  • Order cancellation triggers stock restock logic.
  • Booking total recalculates against selected slot + valid-hour offer.
  • Owner/Admin status updates refresh tables after mutation.

Customer Layer

Discovery and profile flows optimized for quick conversion from search to booking or cart checkout.

Owner Layer

Unified operations across appointments, products, and order fulfillment statuses.

Admin Layer

Marketplace governance for catalog quality, promotions, and order-level intervention.
